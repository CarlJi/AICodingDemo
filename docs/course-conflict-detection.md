# 课程冲突检测功能规划

## Issue 目标与范围
- **目标**：在学生选课流程中引入课程时间冲突检测与提醒机制，阻止或提示学生选择时间重复的课程。
- **范围**：
  - 扩展前端课程数据模型，包含课程时间、授课地点与教师信息。
  - 在选课流程中执行冲突校验，并在 UI 中给出可操作的提示。
  - 为后端 API 预留接口字段（若未来扩展为真实后端服务）。
- **未来工作大纲**：
  - 实现课程时间的标准化表示与比较算法。
  - 支持多教学周、多教学节次的冲突校验。
  - 为冲突记录提供操作日志和审计能力。
  - 将冲突信息同步到通知中心或消息推送渠道。

## 需求、约束与资源
- **现有需求**：
  1. 学生在选课时若存在时间冲突需给出明确提示，并允许学生确认继续或取消操作。
  2. UI 需展示冲突课程的名称、教师与冲突时间段。
  3. 需支持移动端与桌面端响应式布局。
- **约束条件**：
  - 当前仅有本地 mock 数据，无真实后端支撑；需保证未来易于接入后端接口。
  - 课程数据可能存在多教室多教师等复杂情况，需支持多个上课时间段。
  - 需兼容现有状态管理逻辑，不破坏已上线的选课/退课功能。
